# 档案维护中功能

## Context（为什么做）

部分文档老师要重写某位歌手的档案。重写期间该歌手档案需满足三道封存：
1. **主页**：头像叠加"维护中"角标（头像保持原色，不灰度），卡片禁用点击不跳转；
2. **直链兜底**：即使手动输入 `/artists/<id>`，也只显示"档案维护中"占位页，看不到原文；
3. **GitHub 防泄露**：仓库 public，原文不能明文提交。原文明文经 AES-256-GCM 加密成 `_drafts/<id>.md.enc` 密文提交到仓库，外人看到的是密文；老师用密码解密后本地编辑，写完加密回传。

核心矛盾：VitePress 把每个 `.md` 编译成 HTML，原文只要明文在仓库就会被公开。因此"网站不显示 + GitHub 看不到原文"靠**替换 .md 为占位 + 原文加密存档**实现。

## 方案

### 1. 数据层：artists.ts 加 maintenance 字段
**文件**：[artists.ts](file:///e:/codeing/showMD/docs/data/artists.ts)
- `Artist` 接口加 `maintenance?: boolean`
- 封存的歌手数据项加 `maintenance: true`
- [validate-data.mjs](file:///e:/codeing/showMD/scripts/validate-data.mjs) 只校验 id/avatar/songs，新字段不破坏校验，无需改动

### 2. 主页卡片改造
**文件**：[index.md](file:///e:/codeing/showMD/docs/index.md)
- 用 `v-if="artist.maintenance"` 区分两种卡片渲染：
  - **维护中**：头像保持原色（不灰度），叠加"档案维护中"角标（绝对定位右上角，半透明色块+白字）；不渲染为 `<a>`（改 `<div>` 无 href，禁用点击）；悬停浮层文案改"档案正在重新编写中，敬请期待"
  - **正常**：保持现有 `<a>` 链接卡片不变
- 复用现有 `.artist-media` / `.artist-name` 结构，新增 `.artist-maintenance-badge` 角标样式

### 3. 占位页面（封存时写入歌手 .md）
不单独建模板文件（避免被 VitePress 误构建），占位内容内联在封存脚本里。占位 .md 内容：
- frontmatter：`title` / `description` 保留歌手名
- 正文：# 档案维护中 + 说明"该歌手档案正由文档老师重新编写，暂未公开，完成后恢复"

### 4. 原文加密存档（零依赖）
- 用 Node 内置 `crypto` 模块 AES-256-GCM 加密原文明文，输出 base64 文本到 `_drafts/<id>.md.enc`（仓库根目录，与 docs 分离，VitePress 完全不碰）
- 密码从环境变量 `ARCHIVE_KEY` 读取（本地设置，不入仓库；模式同项目里 `NCM_COOKIE`）
- `.enc` 是密文文本，外人打开是一串 base64，无法直接阅读
- `.gitignore` 追加 `_drafts/*.md`（防止明文草稿误提交；`.enc` 密文允许提交）

### 5. 封存/解封辅助脚本
**文件**：新建 [scripts/maintenance.mjs](file:///e:/codeing/showMD/scripts/maintenance.mjs)
- `npm run maintain -- <id>` 封存：① 检查 `ARCHIVE_KEY` 环境变量；② 读 `docs/artists/<id>.md` 原文，AES 加密写入 `_drafts/<id>.md.enc`；③ 把 `<id>.md` 替换为占位内容；④ `artists.ts` 该歌手数据项加 `maintenance: true`
- `npm run maintain -- <id> -- unseal` 解封：① 检查 `ARCHIVE_KEY`；② 解密 `_drafts/<id>.md.enc` 覆盖回 `docs/artists/<id>.md`；③ 删除 `.enc`；④ `artists.ts` 去掉 `maintenance: true`
- **package.json** 加 `"maintain": "node scripts/maintenance.mjs"`
- 加密/解密函数复用 Node `crypto`（createCipheriv / createDecipheriv + GCM authTag），无第三方依赖

### 6. config.ts 导航标识（手动，可选）
**文件**：[config.ts](file:///e:/codeing/showMD/docs/.vitepress/config.ts)
- nav 和 sidebar 里被封存歌手的 `text` 后加「（维护中）」
- 链接保留（点进去即占位页，符合直链兜底）
- 脚本不自动改 config.ts，封存/解封时手动同步两处 text

### 7. 维护教程更新
**文件**：[maintenance.md](file:///e:/codeing/showMD/docs/guide/maintenance.md)
- "工作流 B"后加一节"封存/解封档案"，说明：
  - 设置 `$env:ARCHIVE_KEY="你的密码"`（密码私下告知老师，勿提交）
  - `npm run maintain -- <id>` 封存
  - `npm run maintain -- <id> -- unseal` 解封
  - 手动同步 config.ts nav/sidebar 的「（维护中）」标识

## 验证
1. `npm run docs:dev` 启动本地预览
2. 主页：被封存歌手卡片头像原色 + "维护中"角标 + 点击无反应（鼠标不变成手指）；正常歌手卡片不受影响
3. 直接访问 `/artists/<id>`：显示"档案维护中"占位页，无原文内容
4. `git status`：`_drafts/<id>.md.enc` 已跟踪（密文）；无明文 .md 草稿
5. `npm run validate`：校验通过（maintenance 字段不影响）
6. GitHub 仓库：只有占位 `<id>.md` 和密文 `<id>.md.enc`，搜不到原文明文

## 不做的事
- 不把仓库设为 private（保留 MIT 开源属性）
- 不写前端路由拦截（占位 .md 本身就是兜底，前端拦截无法防源码泄露）
- 不灰度头像（避免像遗照，按用户要求只加角标）
- 不清 git 历史（本功能面向"今后封存"，历史已有内容不在本次范围）
- 不引入 zip 密码第三方依赖（AES-256-GCM 零依赖且更难破解）
